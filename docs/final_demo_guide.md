# Final Demo Guide — Academic + Business Committee

**Positioning:** **Research-validated Decision Intelligence Prototype with a Production Roadmap**

## Start

```bash
python -m venv .venv
# activate the environment
pip install -e ".[data,ml,api,dashboard,dev]"
python scripts/verify_closure_reproducibility.py
streamlit run src/delay_intelligence/dashboard/app.py
```

The dashboard invokes the local FastAPI application through `TestClient`, so a separate API process is not required for the normal dashboard demo. To show Swagger separately:

```bash
uvicorn delay_intelligence.api.main:app --host 127.0.0.1 --port 8000
```

## Evidence language to say out loud

- **REAL DATA:** “These are historical SCMS shipment records.”
- **MODEL OUTPUT:** “This probability, interval, and SHAP explanation are generated by fitted models.”
- **SIMULATED SCENARIO:** “This recommendation and financial impact depend on configurable assumptions.”
- **EXPLORATORY ONLY:** “The causal graph is hypothesis generation, not proof of intervention effect.”
- **NOT VALIDATED:** “DataCo/Olist adapters exist, but external validation has not been completed.”

## Demo journey

### 1. Executive Control Tower

Show the real historical holdout sample and the model-scored portfolio. Explain that the dashboard is ranking/prioritization support, not a live 2026 logistics feed.

Key story:

> “We move from a raw shipment record to calibrated late risk, then to a human-governed decision-support scenario.”

### 2. Shipment Risk Explorer

Select a shipment and show:

- calibrated late probability;
- decision threshold;
- conditional delay P50;
- 90% CQR interval **if late**;
- real local CatBoost SHAP contributions.

Say explicitly:

> “SHAP tells us why the model scored the shipment this way; it is not a causal effect.”

If an exploratory causal edge is shown, use only the phrase **candidate hypothesis**.

### 3. Action Center

Show the model output, then change:

- assumed delay cost/day;
- assumed intervention cost;
- assumed intervention efficacy in days.

Point out that the displayed net benefit changes as the assumptions change. This is the intended proof that the economic number is a **scenario estimate**, not a realized saving.

For the historical E8 artifact, the base 10% review-budget example is:

- modeled Do-Nothing cost: $411,378.96;
- modeled cost-sensitive scenario cost: $379,889.52;
- scenario-based estimated impact: **$31,489.44 (7.65%)**.

Never say “we saved $31K.”

### 4. Portfolio Analytics

Show risk by fulfillment channel and shipment mode. Clarify that these charts aggregate **model outputs** over the demo sample.

### 5. Academic Evidence

This is the most important committee page. Show two result families separately:

1. **Original frozen research artifact** — preserved for provenance.
2. **Patched v2 serving validation** — the exact models/calibrator used by the current live API.

Highlight the v2 holdout classification result:

- PR-AUC 0.2696;
- ROC-AUC 0.8330;
- recall 47.54%;
- Brier 0.0500.

Then show severity uncertainty:

- 95.08% observed coverage on 61 delayed holdout shipments;
- mean interval width 54.92 days.

Say:

> “Coverage is strong here, but sharpness is weak. We expose that trade-off rather than hiding it.”

## Swagger proof that mocks are removed

Open `/docs` and call:

- `/explain` — returns real `shap_contributions`.
- `/recommend` — returns `evidence_label: SIMULATED SCENARIO` and a financial disclaimer.

## Expected difficult questions

**“Is this externally validated?”**  
No. DataCo/Olist are adapter/protocol prototypes only.

**“Is the causal graph proof?”**  
No. It is exploratory hypothesis generation and the legacy mixed-data methodology has documented limitations.

**“Did you really save $31K?”**  
No. It is a modeled scenario under explicit cost/efficacy assumptions.

**“Is this production-ready?”**  
No. It is a research-validated prototype with a production roadmap; recent prospective data, live integrations, security, monitoring, and prospective business-impact validation are still required.

## One-sentence close

> “The value of the prototype is not one algorithm; it is the transparent integration of leakage-safe prediction, calibrated uncertainty, model explanation, decision prioritization, and explicit governance of what is real, modeled, exploratory, and simulated.”
